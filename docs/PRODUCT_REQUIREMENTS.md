# Cresta 제품 요구사항

## 1. 목적

Cresta 첫 버전의 제품 범위와 사용자에게 제공할 거래 통제 기능을 정의한다. 상세 주문 처리와 증권사 연동 규칙은 별도 명세를 따른다.

## 2. 적용 범위

- 국내주식 개인용 단기매매 시스템
- 키움증권 REST API 모의투자 계좌 1개
- 사용자가 직접 등록한 최대 3개 종목
- Ubuntu Server 및 Docker 기반 웹 서비스
- 분석, 사용자 승인, 키움 모의투자 주문 및 거래 기록

실거래, 해외주식, 다중 계좌, 다중 증권사와 종목 자동 추천은 첫 버전에서 제외한다.

## 3. 상세 명세

### 3.1 증권사 및 실행 환경

| ID | 요구사항 |
| --- | --- |
| PRD-001 | 첫 버전의 증권사는 키움증권으로 한다. |
| PRD-002 | Ubuntu/Docker에서 실행 가능한 키움 REST API를 사용하며 Windows OCX 방식은 사용하지 않는다. |
| PRD-003 | 첫 버전은 키움 모의투자 주문까지 연결하고 실거래 주문은 비활성화한다. |
| PRD-004 | 자격증명과 서버 주소는 모의투자와 실거래 환경별로 완전히 분리한다. |
| PRD-005 | Core와 Guard는 키움 고유 필드에 직접 의존하지 않고 Broker 인터페이스만 사용한다. |

### 3.2 행동별 실행 권한

각 주문 가능 행동은 다음 실행 모드 중 하나를 사용한다.

- `AUTOMATIC`: 조건 충족 시 사용자 건별 승인 없이 실행
- `MANUAL_APPROVAL`: 유효시간이 있는 사용자 승인을 받은 뒤 실행
- `DISABLED`: 해당 행동을 실행하지 않음

| ID | 요구사항 |
| --- | --- |
| PRD-010 | 실행 모드는 시스템 전체가 아니라 행동별로 설정할 수 있어야 한다. |
| PRD-011 | 매수, 부분매도, 일반 전량매도, 목표수익 매도, 고정손절, 추적손절, 장 마감 청산과 긴급청산을 각각 설정할 수 있어야 한다. |
| PRD-012 | 시스템 기본값은 일반 매수·매도 `MANUAL_APPROVAL`, 고정손절·장 마감 청산·긴급청산 `AUTOMATIC`으로 한다. |
| PRD-013 | 자동 기능 활성화 및 위험한 설정 변경은 사전 경고와 감사 로그를 남긴다. |
| PRD-014 | 승인 대기 중 자동손절 조건이 발생하면 Guard의 손절 정책을 우선한다. |
| PRD-015 | Guard의 계좌·한도·데이터·중복 주문 검사는 어떤 실행 모드에서도 생략할 수 없다. |

권장 기본값:

```yaml
execution_policy:
  buy: MANUAL_APPROVAL
  partial_sell: MANUAL_APPROVAL
  full_sell: MANUAL_APPROVAL
  take_profit: MANUAL_APPROVAL
  fixed_stop_loss: AUTOMATIC
  trailing_stop: AUTOMATIC
  end_of_day_liquidation: AUTOMATIC
  emergency_exit: AUTOMATIC
```

### 3.3 익일 보유

| ID | 요구사항 |
| --- | --- |
| PRD-020 | 익일 보유 기본값은 금지한다. |
| PRD-021 | 사용자는 전략 또는 종목 설정에서 익일 보유를 허용할 수 있다. |
| PRD-022 | 지원 정책은 `FORBID_OVERNIGHT`, `ALLOW_OVERNIGHT`, `ASK_BEFORE_CLOSE`로 한다. |
| PRD-023 | `FORBID_OVERNIGHT`와 장 마감 청산 `DISABLED`처럼 서로 모순되는 설정은 저장하지 못하게 한다. |
| PRD-024 | 익일 보유 시 포지션, 평균단가, 손절가와 전략 상태를 다음 거래일에 복원한다. |
| PRD-025 | 미체결 신규매수 주문은 익일 보유 대상에 포함하지 않는다. |

### 3.4 사용자 설정의 적용 단위

설정 우선순위는 다음과 같다.

```text
Guard의 변경 불가 안전한도
→ 종목별 설정
→ 사용자 기본 설정
→ 시스템 기본값
```

설정에는 버전을 부여한다. 주문 판단과 승인 기록에는 사용된 설정 버전을 저장하여 나중에 재현할 수 있어야 한다.

### 3.5 Web UI 설정 제공

| ID | 요구사항 |
| --- | --- |
| PRD-030 | 행동별 실행 방식, 감시·거래시간, 주문·미체결, 익일 보유와 Guard 리스크 정책을 모두 Web UI에서 조회·설정할 수 있어야 한다. |
| PRD-031 | 설정 변경은 서버 검증, 영향 미리보기와 사용자 확정 절차를 거쳐야 한다. |
| PRD-032 | 설정 변경 이력과 실제 적용 버전을 Web UI에서 조회할 수 있어야 한다. |
| PRD-033 | 중복 주문 방지, 재동기화, 비밀정보 보호와 감사 로그 같은 시스템 무결성 규칙은 상태만 표시하고 비활성화할 수 없게 한다. |
| PRD-034 | 첫 키움 모의투자 주문 통합시험은 서버 CLI가 아닌 Web UI에서 실행하며, MOCK·KRX·매수 1주로 제한하고 정상 주문과 구분해 감사한다. |

### 3.6 다중 에이전트와 모델 공급자

| ID | 요구사항 |
| --- | --- |
| PRD-040 | AI 판단은 정보수집, 증거 검증, 역할별 평가와 최종 Core 판단을 분리한 다중 에이전트 구조를 지원한다. |
| PRD-041 | 에이전트는 자유로운 상호 명령이 아니라 버전 관리된 DAG, 불변 입력과 구조화 출력으로 연결한다. |
| PRD-042 | OpenAI·Anthropic·Gemini 공식 API, Vercel AI Gateway, 승인된 OpenAI 호환 Gateway와 Ollama를 교체 가능한 Adapter로 지원할 수 있어야 한다. |
| PRD-043 | 사용자는 Web UI에서 역할별 provider·model·fallback·한도와 SHADOW 상태를 설정하되 credential은 write-only 보안 절차로 관리한다. |
| PRD-044 | 신규 agent·provider·model·prompt는 SHADOW 검증을 거치며 provider 장애·출력 오류가 Guard를 우회하거나 신규매수를 허용해서는 안 된다. |

## 4. 오류·예외 또는 경계 조건

- 모의투자에서 지원하지 않는 기능은 성공한 것처럼 모방하지 않고 `UNSUPPORTED_IN_MOCK`으로 표시한다.
- 사용자가 자동 기능을 활성화해도 데이터 지연, 계좌 불일치, 주문 상태 불명확 시 신규매수는 차단한다.
- 손절과 긴급청산은 손실률이나 체결가격을 보장하지 않으며 주문 실행을 시도하는 기능으로 설명한다.
- 외부 앱에서 발생한 주문이나 포지션은 계좌 재동기화 절차로 감지한다.

## 5. 검증·인수 조건

- 모든 주문 가능 행동에 독립적인 실행 모드를 저장하고 조회할 수 있다.
- 자동, 승인, 비활성 모드가 각각 주문 흐름에 반영된다.
- 익일 보유 금지와 허용 정책에 따라 장 마감 처리 결과가 달라진다.
- 모순되는 설정 조합이 API와 UI 양쪽에서 거부된다.
- 모의투자 자격증명으로 실거래 서버에 접근할 수 없고 반대 경우도 동일하다.
- 다중 에이전트와 provider를 변경해도 구조화 판단·Guard·승인·주문 경계가 유지된다.

## 6. 미결정·보류 항목

첫 버전 제품 범위의 내부 미결정 항목은 없다. 전략 템플릿과 실거래는 범위에서 제외하며, 긴급청산 실행 모드는 설정 가능하지만 변경 불가 Guard 중지를 우회할 수 없다.
