# Cresta Web UI 명세

## 핵심 모의투자 Guard 제어

- 대시보드 Guard 카드에서 현재 `PAUSE_ENTRY` 상태를 항상 표시한다.
- 사용자는 확인과 5자 이상의 사유 입력 후 신규 매수 중지를 활성화하거나 해제할 수 있다.
- 활성 상태는 신규 BUY만 차단하며 기존 포지션 조회와 청산 판단은 계속 허용한다.

## 1. 목적

사용자가 키움 모의투자 기반 Cresta의 감시 종목, 전략, 행동별 실행 권한, 주문·승인, 포지션, Guard 정책과 시스템 상태를 안전하게 관리할 수 있는 Web UI를 정의한다.

`stitch_cresta_ai_intraday_trading_system`의 화면과 디자인 시스템은 시각적 콘셉트 자료로 사용하지만, 제품 요구사항과 상세 명세가 우선한다.

## 2. 적용 범위

- 데스크톱·태블릿·모바일 반응형 Web UI
- 대시보드, 감시종목, 보유 포지션, 승인·주문, AI 판단
- 거래·Guard 설정, 설정 버전과 영향 미리보기
- 비상정지, 재동기화와 시스템 상태
- 이력·감사 로그
- ID·비밀번호·TOTP 로그인과 고위험 행동 재인증

## 3. 상세 명세

### 3.0 로그인과 인증 화면

로그인 흐름:

```text
사용자 ID·비밀번호 입력
→ 서버 검증
→ TOTP 6자리 입력
→ 인증 완료
→ 대시보드 이동
```

| ID | 요구사항 |
| --- | --- |
| UI-AUTH-001 | 미인증 사용자는 로그인 화면 외의 Console 화면과 실시간 연결에 접근할 수 없다. |
| UI-AUTH-002 | 로그인 화면은 사용자 ID, 비밀번호와 TOTP를 요구하며 오류 원인이 ID·비밀번호·TOTP 중 무엇인지 구분해 노출하지 않는다. |
| UI-AUTH-003 | TOTP 입력은 숫자 6자리, 붙여넣기와 모바일 숫자 키패드를 지원하되 값을 로그·URL·브라우저 저장소에 보존하지 않는다. |
| UI-AUTH-004 | 로그인 실패·잠금·만료 상태는 안전한 일반 메시지와 다시 시도 가능한 시점만 표시한다. |
| UI-AUTH-005 | 세션 만료 시 보호된 내용을 숨기고 로그인 화면으로 이동하며 작성 중이던 주문·승인 요청을 자동 재실행하지 않는다. |
| UI-AUTH-006 | 주문 승인·위험 한도 완화·비상정지 해제 등은 별도 TOTP 재인증 모달을 사용하고 대상 행동을 명시한다. |
| UI-AUTH-007 | 로그아웃은 서버 세션과 실시간 연결을 종료하고 로그인 화면으로 이동한다. |

세부 인증·세션·복구 정책은 [인증 및 보안 명세](SECURITY_SPEC.md)를 따른다.

첫 구현에서는 로그인과 Console shell을 같은 origin으로 제공한다. CSRF token은 페이지 메모리에만 두고 새로고침 때 서버 세션 확인 API로 회전한다. Console에 아직 Backend가 없는 거래 기능은 샘플 수치를 표시하지 않고 `준비 중` 또는 `연결 전` 상태로 명확히 비활성화한다.

### 3.1 디자인 기준

재사용할 콘셉트:

- 깊은 네이비 기반 다크 모드

- 데스크톱 고정 사이드바와 상단 상태바
- 금융 숫자의 고정폭·tabular figures
- 상태 코드의 pill badge
- 실시간 변화를 위한 짧은 강조 효과
- 경고·위험 행동을 제한적으로 강조하는 색상 체계

| 콘셉트 예시 | 실제 Cresta 적용 |

| Full Auto 단일 토글 | 행동별 `AUTOMATIC/MANUAL_APPROVAL/DISABLED` |
| 감시 종목 4개 이상 | MVP 최대 3개 |
| 1·3·5분 분석 | 집중 5·10분, 일반 10·30분 기본 선택 |

| UI-003 | 환경, 거래소, 연결과 재동기화 상태를 모든 주요 화면에서 확인할 수 있어야 한다. |

#### 3.6.1 첫 Paper Broker Console 연동

첫 연동 화면은 Backend에 실제 저장된 Paper 주문·체결·포지션만 조회한다. 데이터가 없으면 `EMPTY` 상태를 표시하며 데모 수치나 브라우저에서 생성한 주문을 표시하지 않는다.

| ID | 요구사항 |
| --- | --- |
| UI-PAP-001 | 대시보드는 DB, Paper Broker, 거래 게이트, 키움 Broker와 시장데이터 상태를 `/system/health` 응답으로 표시한다. |
| UI-PAP-002 | 승인·주문 화면은 주문 방향·유형·가격·요청/체결/취소/잔량·상태·시각을 표시하고 상태 코드를 텍스트로 병기한다. |
| UI-PAP-003 | 주문을 선택하면 체결과 상태 이벤트를 시간순으로 표시하며 `UNKNOWN`을 실패로 바꾸거나 재시도 버튼을 제공하지 않는다. |
| UI-PAP-004 | 보유 포지션 화면은 legacy Paper 원장과 키움 MOCK account projection의 총수량·매도가능수량·Broker 평균단가·Cresta 관리수량·관리평균단가·외부수량·상태·version을 표시한다. `CRESTA_MANAGED`·`EXTERNAL`·`MIXED`를 명확히 구분하며 현재가와 손익 데이터가 없으면 계산하거나 추정하지 않는다. |

## 4. 오류·예외 또는 경계 조건

- UI에서 성공 메시지를 표시하기 전에 서버의 활성 설정 버전 또는 주문 상태를 확인한다.
- 인증 실패 후 입력한 비밀번호와 TOTP를 화면에 다시 채우거나 자동 재전송하지 않는다.
- 세션 만료 후 기존 주문 승인 화면으로 돌아와도 사용자가 명시적으로 다시 확인하기 전에는 요청하지 않는다.
- 두 브라우저에서 설정을 동시에 수정하면 오래된 버전 저장을 거부하고 차이를 표시한다.
- 비상정지 중에도 화면 상태와 포지션 조회는 유지한다.
- 모바일 화면에서 위험 확인 정보를 생략해 버튼만 노출하지 않는다.
- 콘셉트 HTML에 포함된 비밀값 예시는 실제 UI·fixture·문서로 복사하지 않는다.
- 키움 모의투자에서 검증할 수 없는 NXT 주문 컨트롤은 비활성화하고 이유를 표시한다.

## 5. 검증·인수 조건

- 기존 콘셉트의 시각 언어를 유지하면서 국내주식·키움 모의투자 정보로 표시된다.
- 사용자 ID·비밀번호·TOTP를 모두 검증하지 않으면 보호된 화면에 접근할 수 없다.
- 모든 거래·Guard 정책을 Web UI에서 조회·편집하고 영향 미리보기를 확인할 수 있다.
- API Key·Secret·토큰 원문이 DOM, 화면, 로그에 노출되지 않는다.
- 행동별 실행 모드와 설정 출처·버전을 조회할 수 있다.
- 승인 만료·가격 이탈·데이터 지연 시 잘못된 주문 승인을 할 수 없다.
- `UNKNOWN`, 재동기화, 부분체결과 외부 주문 상태가 명확히 표시된다.
- 비상정지 수준별 영향과 해제 조건이 일관되게 표시된다.
- 데스크톱·태블릿·모바일과 키보드 접근성 검증을 통과한다.

## 6. 미결정·보류 항목

- 첫 버전 기본 언어는 한국어이며 다국어 전환은 제외한다.
- 차트는 서버의 1분봉 조회만 사용하고 tick 전체를 브라우저에 내려보내지 않는다. 라이브러리는 구현 전에 라이선스·접근성 검토 후 선택한다.
- 첫 버전 알림은 화면 내 알림과 운영 로그로 제한하고 브라우저·모바일 push는 제외한다.
- 위젯 배치는 고정하고 데스크톱의 정보 밀도 `COMPACT/COMFORTABLE`만 지원한다.
- 설정은 영역별 탭, 감시종목 등록은 단계별 마법사를 사용한다.

- Provider registration selects one of 40 server catalog entries, shows unavailable authentication types as disabled, and renders template-specific configuration fields.
